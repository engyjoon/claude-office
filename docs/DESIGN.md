# Claude Office 설계서 (v0.2)

> Claude Code 에이전트들이 일하는 모습을 보여주는 macOS 네이티브 가상 사무실 앱
>
> - 앱 이름: **Claude Office** (번들 ID `com.engyjoon.claudeoffice`)
> - 문서 상태: v0.3. **M1(코어) 구현 완료** — 구현하면서 바뀐 점은 §6.4에 정리했습니다. v0.2에서 바뀐 점: 앱 이름, 효과음(§11), 미니 사무실 크기 조절(§10.1), Claude Code 2.1.318 훅 확인 결과(§4)

## 1. 개요

### 1.1 목표

- 개발 노트북에서 코딩하는 동안 **Claude Code 세션과 서브에이전트의 상태를 한눈에** 볼 수 있게 합니다.
- 상태를 숫자나 로그가 아니라 **아기자기한 캐릭터가 일하는 사무실**로 보여줍니다. 캐릭터는 말풍선으로 대화하고, 표정과 제스처로 감정을 표현합니다.
- 실제로 쓸모 있는 신호를 놓치지 않게 합니다. 특히 **권한 승인 대기**는 즉시 눈에 띄어야 합니다.
- 하루 종일 띄워둬도 부담이 없어야 합니다 (저전력, 포커스를 빼앗지 않음).

### 1.2 비목표 (MVP 범위 밖)

- 앱에서 에이전트에게 지시하거나 권한을 승인·거부하는 기능 (v2 검토)
- 여러 사람이 함께 쓰는 팀 공유 사무실 (v2 이후)
- Windows, Linux 지원
- App Store 배포 (샌드박스 제약, §12 참고)

### 1.3 확정된 결정 사항

| # | 항목 | 결정 |
|---|---|---|
| ① | 캐릭터 단위 | 사용자가 직접 연 세션 = **메인**(★ 배지), 그 메인이 띄운 세션과 모든 서브에이전트(기본 에이전트, `.claude/agents/*.md`로 직접 만든 에이전트) = **서브**. 사무실에 메인이 1명이면 "메인", 여럿이면 "메인1·2…"(출근 순서, 번호 고정·빈 번호 재사용). 서브는 메인마다 따로 1명이면 "서브", 여럿이면 "서브1·2…". 에이전트 종류는 신원 카드에만 보여 줍니다. 직접 만든 에이전트는 내부적으로 같은 얼굴을 유지합니다 (2026-11-08 결정, ~~팀장·팀원~~, ~~파트장·파트원~~) |
| ② | 사무실 구성 | **메인 하나 = 행 하나**. 가장 왼쪽 책상이 메인, 오른쪽으로 그 메인의 서브 책상이 사람 수만큼(빈 책상 없음). 행은 위에서 아래로 최대 3개(창이 3행 높이보다 낮아지지 않음). 오른쪽 패널 위 **디렉토리** 드롭다운(Claude 데스크톱 앱에 열린 디렉토리)으로 볼 디렉토리를 하나 고름("모두" 가능), 그 아래 **세션** 목록. 사무실은 줄이지 않고(배율 1) 들어가는 만큼만 그림 (§5.1, §8.1, M5(1)) |
| ③ | 상호작용 | 보기 + 알림 + 클릭하면 상세 정보 / 터미널로 이동 |
| ④ | 공개 범위 | 본인용으로 시작하되 오픈소스 공개를 염두에 둡니다. **그래픽과 효과음은 모두 직접 제작**한 에셋만 사용합니다 |
| ⑤ | 앱 이름 | **Claude Office** |
| ⑥ | 캐릭터 말투 | 모든 캐릭터가 밝고 정중한 **해요체**로 통일 |
| ⑦ | 효과음 | 작고 아기자기한 합성음. **종류별로 켜고 끌 수 있음** (§11) |
| ⑧ | 미니 사무실 | 기본 위치는 화면 **오른쪽 아래**, 크기는 **자유롭게 조절** (§10.1) |
| 기술 | 기본값 | macOS 14+, SwiftUI + AppKit + SpriteKit, `127.0.0.1` HTTP 수신, 훅 우선(JSONL은 2단계), SwiftPM 코어 + XcodeGen, 소스 빌드 배포 |

## 2. 사용 시나리오

1. **아침 출근:** 터미널에서 `claude`를 실행하면 사무실 문이 열리고 메인 캐릭터가 들어와 새 행의 가장 왼쪽 책상에 앉습니다.
2. **업무 지시:** 프롬프트를 입력하면 종이비행기가 날아와 메인에게 도착하고, 메인 머리 위에 💡가 뜹니다.
3. **위임:** 메인이 서브에이전트(`code-reviewer`)를 호출하면 고정 직원 "코드리뷰어"가 문으로 들어옵니다. 메인 자리로 걸어와 대화한 뒤(메인: "RouterConfig 리뷰 부탁해요!" / 서브: "맡겨주세요!") 오른쪽 끝에 새로 생긴 자기 책상에 앉습니다.
4. **작업 중:** 파일을 읽으면 자료를 넘기고, 편집하면 타이핑하고, 오래 걸리는 명령을 실행하면 자기 책상에서 모니터를 보며 기다립니다 (⏳, M4.5b).
5. **승인 대기:** 권한 요청이 생기면 캐릭터가 일어나 손을 들고 ❗ 말풍선("`npm test` 실행해도 될까요?")을 띄웁니다. 메뉴바 아이콘에 배지가 붙고 macOS 알림이 옵니다. 알림을 클릭하면 해당 터미널이 앞으로 나옵니다.
6. **완료 보고:** 서브에이전트가 끝나면 메인에게 걸어와 하이파이브를 하고("다 했어요!") 퇴근합니다. 메인이 응답을 마치면 기지개를 켭니다.
7. **휴식:** 오래 대기 상태가 이어지면 휴게실에서 커피를 마시고, 더 길어지면 책상에서 꾸벅꾸벅 좁니다(💤).
8. **퇴근:** 세션이 끝나면 손을 흔들고 문으로 나갑니다.

## 3. 시스템 아키텍처

```
┌──────────────── Claude Code (여러 세션) ────────────────┐
│  hooks: SessionStart / UserPromptSubmit / PreToolUse /    │
│         PostToolUse / Notification / Stop / Subagent* …   │
└───────────────┬───────────────────────────────────────────┘
                │ stdin JSON → claude-office.sh → curl (동기, 최대 1초)
                ▼
┌──────────────────────── Claude Office.app ─────────────────────────┐
│ [HookServer]  127.0.0.1:47821  POST /v1/hook  (토큰 검증)          │
│      │                                                            │
│      ▼                                                            │
│ [OfficeCore]  ← 순수 Swift, Linux에서도 빌드·테스트 가능            │
│   HookParser → OfficeEvent → OfficeReducer → OfficeState          │
│                                  │                                │
│                           Choreographer (연출 결정, 시간 주입)      │
│                                  │  [Directive]                   │
│      ┌───────────────────────────┼───────────────────────┐        │
│      ▼                           ▼                       ▼        │
│ [OfficeScene: SpriteKit]   [SwiftUI: 메뉴바·인스펙터]  [Notifier]    │
│  캐릭터 리그, 말풍선, 길찾기   상태 목록, 설정, 훅 설치   UNUserNotif.  │
└───────────────────────────────────────────────────────────────────┘
```

**설계 원칙**

- **판단은 코어, 연출은 씬.** "무엇을 보여줄지"는 모두 `OfficeCore`의 순수 함수가 결정하고, 결과를 `Directive` 목록으로 내보냅니다. SpriteKit 씬은 받은 지시를 그대로 그리기만 합니다. 이렇게 나누면 핵심 로직을 리눅스 클라우드 세션에서도 테스트할 수 있습니다.
- **Claude Code를 절대 방해하지 않습니다.** 훅 스크립트는 항상 즉시 `exit 0`하고, 아무것도 출력하지 않으며, 앱이 꺼져 있어도 조용히 넘어갑니다.
- **모르는 이벤트는 무시합니다.** Claude Code 버전에 따라 훅 필드가 달라질 수 있으므로, 파서는 관대하게 만들고 알 수 없는 필드와 이벤트는 버립니다.

## 4. 이벤트 수집

### 4.1 구독할 훅 이벤트

| 훅 이벤트 | 주요 필드 (공통: `session_id`, `cwd`, `transcript_path`, `hook_event_name`) | 용도 |
|---|---|---|
| `SessionStart` | `source` (startup / resume / clear / compact) | 팀장 출근, 팀 구역 배정 |
| `SessionEnd` | `reason` | 팀장 퇴근 |
| `UserPromptSubmit` | `prompt` | 새 업무 도착 연출 (프롬프트 내용은 기본적으로 표시하지 않음) |
| `PreToolUse` | `tool_name`, `tool_input`, `tool_use_id` | 활동 시작. `Agent` 툴(구버전 이름 `Task`)이면 서브에이전트 위임 |
| `PostToolUse` | `tool_name`, `tool_response`, `tool_use_id` | 활동 종료 (성공) |
| `PostToolUseFailure` (지원 버전만) | `tool_name`, 오류 정보 | 툴 오류 연출. 없으면 `tool_response`로 판단 |
| `Notification` | `message`, (버전에 따라) `notification_type` | 권한 승인 대기, 입력 대기 |
| `PermissionRequest` (지원 버전만) | `tool_name`, `tool_input` | 권한 대기를 더 정확하게 감지 (관찰만 하고 결정은 돌려주지 않음) |
| `Stop` | `stop_hook_active` | 팀장 응답 완료 |
| `SubagentStart` (지원 버전만) | `agent_id`, `agent_type` | 팀원 출근 (정확한 식별) |
| `SubagentStop` | `agent_id`, `agent_type`, `agent_transcript_path`, `last_assistant_message` | 팀원 작업 완료 → 보고 후 퇴근 |
| `PreCompact` | `trigger` | "서류 정리 중" 연출 |

> **Claude Code 2.1.318에서 확인한 사실** (실행 파일의 훅 스키마 기준)
> - `SubagentStart`, `PermissionRequest`, `PostToolUseFailure`, `PermissionDenied`, `StopFailure` 등 이벤트가 있습니다.
> - 서브에이전트 안에서 발생한 훅에는 **`agent_id`와 `agent_type`이 붙습니다.** 메인 스레드에서는 `agent_id`가 없습니다.
> - `Notification.notification_type`에는 `permission_prompt`, `idle_prompt` 등이 들어옵니다.
>
> **M0 실제 수집 결과** (2026-11, Claude Code 2.1.318, macOS, 98건, iTerm.app·vscode)
> - 위 필드 구성이 실제와 일치했습니다. 서브에이전트 안의 툴 이벤트에는 `agent_id`·`agent_type`이 붙어 옵니다.
> - 처음 보는 공통 필드: `scratchpad_dir`, `effort.level`, Stop/SubagentStop의 `session_crons` (사용하지 않음, 무시).
> - 처음 보는 툴 `SubagentHandback`(입력: `message`): 서브에이전트가 결과를 넘기는 동작으로 보고 "보고 정리 중" 연출(서류 정리 자세)로 처리합니다. 메시지 내용은 표시하지 않습니다.
> - **서브에이전트 유형 3가지** (`capture.py breakdown`으로 확인):
>   1. **일반 위임** (`general-purpose` 등): `Agent` 위임 → `SubagentStart` → 툴 이벤트(`agent_id` 포함) → `SubagentHandback` → `SubagentStop` → `PostToolUse(Agent)`.
>   2. **신호 없는 위임** (`web-fetch`): `Agent` 위임 → 툴 이벤트만 오고 `SubagentStart`/`SubagentStop`이 없습니다 → `PostToolUse(Agent)`로 끝납니다.
>   3. **Claude Code 내부 작업**: `agent_type`이 빈 `SubagentStop` 하나만 옵니다 (16건 중 14건). 다른 이벤트가 없고 사용자가 맡긴 일이 아니므로 **무시**합니다.
> - 그래서 팀원 종료 규칙을 이렇게 정했습니다: `SubagentStart`를 받은 팀원과 백그라운드 위임은 `SubagentStop`으로, 그 밖에는 `PostToolUse(Agent)`로 끝냅니다. 종류가 빈 신호는 무시합니다. 안전장치로, 팀장의 응답이 끝날 때(`Stop`) 남은 포그라운드 팀원은 보고하고 퇴근합니다.
> - 메인의 `Bash` 하나가 끝나지 않은 채 남은 경우가 있었습니다 (중단 추정). 팀장의 `Stop`/새 프롬프트에서 진행 중인 툴을 비우므로 화면에 남지 않습니다.
> - `TERM_PROGRAM`: iTerm2는 `iTerm.app`, VS Code 터미널은 `vscode`.
> - `idle_prompt` 알림은 이번 수집에 없었습니다 (파서는 처리함).
>
> ⚠️ **M0에서 반드시 확인할 것:** 필드 구성은 Claude Code 버전마다 다를 수 있습니다. 구현 전에 사용 중인 버전에서 실제 페이로드를 수집해 테스트 픽스처로 저장하고([M0 안내](M0-capture.md)), 파서는 그 픽스처를 기준으로 만듭니다.

### 4.2 훅 스크립트

`~/.claude/hooks/claude-office.sh`에 설치합니다. 원본은 `Sources/OfficeServer/Resources/claude-office.sh`이고 앱 번들에 들어 있습니다 (아래는 요약). 테스트용으로 `CLAUDE_OFFICE_ENDPOINT` 환경 변수로 엔드포인트 파일 위치를 바꿀 수 있습니다.

```sh
#!/bin/sh
# 아무것도 출력하지 않고 항상 exit 0. 앱이 꺼져 있으면 연결이 바로 거부되어 즉시 끝납니다.
ENDPOINT_FILE="${CLAUDE_OFFICE_ENDPOINT:-$HOME/Library/Application Support/ClaudeOffice/endpoint}"
[ -r "$ENDPOINT_FILE" ] || { cat >/dev/null; exit 0; }
read -r PORT TOKEN < "$ENDPOINT_FILE"
curl -s --connect-timeout 0.3 -m 1 -X POST \
  -H "Content-Type: application/json" \
  -H "X-Office-Token: $TOKEN" \
  -H "X-Office-Term: ${TERM_PROGRAM:-unknown}" \
  -H "X-Office-Host-Session: ${CLAUDE_CODE_HOST_SESSION_ID:-}" \
  --data-binary @- "http://127.0.0.1:$PORT/v1/hook" >/dev/null 2>&1
exit 0
```

> **동기 전송인 이유 (M2 첫 실행에서 발견):** 처음에는 curl을 백그라운드로 띄우고 바로 끝냈는데, Claude Code는 훅을 별도 프로세스 그룹에서 실행하고 훅이 끝나면 그룹 전체를 종료합니다. 그래서 백그라운드 curl이 보내기 전에 죽어 훅이 하나도 도착하지 않았습니다. 지금은 응답(202)을 받을 때까지 기다리며, 앱이 응답하기 전에 바로 202를 돌려주므로 보통 수 밀리초 안에 끝납니다. 이벤트가 순서대로 도착하는 효과도 있습니다. `OfficeServerTests`의 "프로세스 그룹이 종료되어도" 테스트가 이 경우를 재현합니다.

- `X-Office-Term`으로 iTerm2, Apple Terminal, VS Code, Ghostty 등을 구분합니다. "터미널로 이동" 기능에 씁니다.
- `X-Office-Host-Session`(M4.5a)은 Claude 데스크톱 앱 세션의 id(`local_…`)입니다. 데스크톱 앱이 훅 프로세스에 `CLAUDE_CODE_HOST_SESSION_ID`로 넘겨 주며, 터미널 세션에서는 비어 있습니다. 서버는 `local_` + 영숫자·하이픈 형식일 때만 받습니다 (파일 경로에 쓰기 때문). 이 헤더가 추가되어 스크립트 내용이 바뀌었으므로, 이전 스크립트가 설치된 맥에서는 메뉴바에 "훅 스크립트를 업데이트해야 해요"가 뜹니다.
- `endpoint` 파일에는 앱이 실행될 때마다 `포트 토큰`을 기록합니다. 기본 포트는 47821이며, 사용 중이면 다른 포트를 고르고 파일을 갱신합니다.

**설치기 동작 규칙**

1. `~/.claude/settings.json`을 `settings.json.bak-YYYYMMDD-HHMMSS`로 백업합니다.
2. 기존 훅은 그대로 두고, 우리 항목만 추가합니다. 우리 항목은 명령 경로(`claude-office.sh`)로 구분합니다.
3. 여러 번 실행해도 결과가 같아야 합니다(멱등성).
4. 제거는 우리 항목만 지웁니다.
5. 프로젝트별 `.claude/settings.json`과 관리형(managed) 설정은 건드리지 않습니다.

### 4.4 서브에이전트 식별

| 상황 | 처리 |
|---|---|
| 페이로드에 `agent_id` / `agent_type`이 있음 (2.1.318 확인) | 그대로 사용합니다. 툴 이벤트에 `agent_id`가 있으면 그 팀원의 활동, 없으면 팀장의 활동입니다 |
| `PreToolUse(Task/Agent)`만 있음 | `tool_input.subagent_type`, `description`으로 팀원을 만들고, `tool_use_id`로 시작과 종료를 짝짓습니다 |
| (구버전 대비) `agent_id`가 없어 누가 했는지 알 수 없음 | 그 세션에 활성 팀원이 한 명이면 그 팀원에게, 여러 명이면 "팀 공용 활동"으로 처리합니다 (팀 구역에 아이콘만 표시) |

툴 이름은 버전에 따라 `Task` 또는 `Agent`일 수 있으므로 둘 다 처리합니다.

**세션의 부모 (M4.5a).** 훅 페이로드에는 "이 세션을 어느 세션이 띄웠는지"가 없습니다. 그래서 데스크톱 앱이 남기는 세션 정보 파일을 **읽기만** 합니다 (공개 API가 아니므로 형식이 바뀌면 조용히 폴더 규칙으로 대체).

- 위치: `~/Library/Application Support/Claude/claude-code-sessions/<계정>/<조직>/<local_id>.json`
- 쓰는 필드: `cliSessionId`(= 훅 `session_id`), `spawnedFrom.sessionId`(부모 `local_id`, 사용자가 직접 연 메인 세션에는 없음), `title`, `originCwd`/`cwd`
- 앱(`OfficeServer.DesktopSessionDirectory`)이 헤더의 `local_id`로 파일을 찾고, 부모를 따라 최상위까지 올라가(최대 8단계, 순환 방지) `SessionHint { ancestors(가까운 부모부터, 훅 session_id), rootCwd(최상위 세션 폴더), title }`를 만들어 이벤트에 붙입니다. 파일은 10초 캐시하고, 못 찾으면 2초 뒤 다시 찾습니다 (SessionStart 시점에 파일이 아직 없을 수도 있어서).
- 코어(`OfficeCore`)는 파일을 모르고 힌트만 받습니다. 힌트가 늦게 와도(파일이 나중에 생김) 다음 이벤트에서 반영합니다 (§5.1).

### 4.5 고정 직원 프로필 수집

- `~/.claude/agents/*.md`와 각 팀 `cwd`의 `.claude/agents/*.md`를 읽어 frontmatter의 `name`, `description`을 가져옵니다.
- `name`이 고정 직원의 키가 됩니다. 외형은 이름 해시로 결정해서 항상 같게 유지하고, 사용자가 앱에서 바꿀 수 있습니다(§9.4).
- `general-purpose`처럼 기본 제공되는 서브에이전트는 **임시 직원**으로 처리합니다. 출근할 때마다 외형이 바뀌고, 머리에 새싹 🌱 액세서리를 답니다.

### 5.1 메인·서브·행 (M5(1), 2026-11-08 개정)

사용자는 Claude 데스크톱 앱에서 메인 세션을 여러 개 열고, 거기서 세션을 더 띄워 일합니다. 사무실의 단위는 **메인 하나 = 행 하나**입니다.
(M4.5a의 "같은 폴더 = 한 방, 나중 세션 = 파트장/팀원" 규칙과 M4.5b의 팀장실·파트 칸은 이것으로 바뀌었습니다. 기록은 §6.8·§6.9.)

| 개념 | 코드 | 설명 |
|---|---|---|
| 행 | `Team` (`TeamID` = `<폴더>#<열린 순번>`) | 메인 하나와 그 서브들. `name`(폴더 이름), `folder`, `island`(메인 번호 자리, 메인 번호 = island + 1), `order`(열린 순서 = 위에서 아래로) |
| 세션 기록 | `Part` (`state.parts[session]`) | 세션 하나(메인 또는 서브 세션). `order`(들어온 순서), `ancestors`(데스크톱 정보의 조상), `title`(데스크톱 세션 제목) |
| 직함 | `JobTitle` (`Agent.title`), `Agent.number` | `.main(n)`("메인" 또는 "메인1·2…", number 0), `.sub(n)`("서브" 또는 "서브1·2…", 행마다 따로) |
| 책상 | `Seat(desk:)` (`Agent.seat`) | 0 = 메인 책상(가장 왼쪽), 서브는 1번부터 빈자리 없이 |

규칙:

1. **메인 판별** — 데스크톱 세션 정보에 부모(`spawnedFrom`)가 없거나 부모가 사무실에 없으면 새 행을 열고 메인이 됩니다. 같은 폴더에서 직접 연 두 번째 세션, 터미널 CLI 세션(데스크톱 정보 없음)도 각자 메인입니다. 행 이름은 최상위 세션 폴더(없으면 자기 폴더) 이름이고, `…/.claude/worktrees/<이름>`은 원래 폴더로 합칩니다.
2. **서브** — 조상 중 사무실에 있는 가장 가까운 세션의 행에 서브로 들어갑니다 (손자 세션도 같은 메인의 서브). 그 행의 세션들(메인·서브 세션)이 부른 모든 서브에이전트(기본·직접 만든 에이전트)도 그 행의 서브입니다.
3. **번호** — 메인은 사무실 전체에서 1명이면 "메인", 2명 이상이면 "메인N"(행이 열릴 때 비어 있는 가장 작은 번호, 고정). 서브는 행마다 1명이면 "서브", 2명 이상이면 "서브N"(출근 때 비어 있는 가장 작은 번호, 고정). 1명 ↔ 여럿이 바뀌면 표시가 바뀝니다 (`Beat.retitled`). 에이전트 종류는 신원 카드의 "에이전트" 줄에만 보여 줍니다. 메인 번호를 다시 써도 행 순서는 메인이 온 순서라, 새 메인은 언제나 맨 아래 행입니다.
4. **책상** — 메인은 0번, 새 서브는 오른쪽 끝(사람 수 번째) 책상. 가운데 서브가 퇴근하면 **오른쪽 끝 사람만** 그 책상으로 옮겨 앉고(`Beat.reseated`) 끝 책상을 치웁니다. 앉아 있는 사람들이 줄줄이 밀려나지 않고, 빈 책상도 남지 않습니다. 서브 번호와 책상 순서는 다를 수 있습니다.
5. **늦게 온 부모** — 하위 세션이 먼저 이벤트를 보내 자기 행의 메인이 되었다가 부모가 오면, 부모가 메인 책상을 넘겨받고 먼저 온 세션은 오른쪽 끝 서브가 됩니다. 하위 세션 여럿이 각자 행을 열었으면 부모의 행 하나로 합칩니다. 정보 파일이 늦게 생겨 다른 메인의 하위로 밝혀진 메인도 그 행으로 옮기고(사람들은 책상 순서대로 오른쪽 끝에 서브로), 원래 행은 닫습니다 (`Beat.teamClosed`). 정보가 서로를 부모로 가리키면(순환) 그대로 둡니다.
6. **승진** — 메인 세션이 끝나면 그 메인의 서브에이전트도 함께 퇴근하고, 남은 서브 세션 중 가장 먼저 온 세션이 메인 책상으로 승진합니다 (`Beat.promoted` → 정보 갱신, 이동, "제가 메인 자리를 맡을게요!"). 사람이 모두 떠난 행은 닫힙니다.
7. **얼굴** — 세션 직원은 세션 id(`session#<id>`), 직접 만든 에이전트는 종류 이름, 기본 에이전트는 출근 순번으로 외형이 정해집니다. 메인 ↔ 서브가 바뀌어도 얼굴은 그대로입니다.

---|---|---|
| 방 | `Team` (`TeamID` = 방 폴더) | 메인 세션 하나와 그 세션이 띄운 세션들. 같은 폴더에서 직접 연 두 번째 메인 세션과 터미널(CLI) 세션도 같은 방에 파트장으로 합류합니다. 사무실에서는 팀장실 + 파트 칸 (M4.5b, §8.1) |
| 파트 (내부 개념) | `Part` (`state.parts[session]`) | 세션 하나와 그 세션이 부른 서브에이전트 묶음. `number` 0 = 팀장의 파트, 1… = 다른 세션의 파트 = 칸 번호 (출근 때 고정, 빈 번호 재사용). `order`(방에 들어온 순서), `ancestors`, `title`(데스크톱 세션 제목). 화면에는 "파트"라는 말을 쓰지 않고 "팀장 칸", "팀원1 칸"으로 보입니다 |
| 직함 | `JobTitle` (`Agent.title`), `Agent.number` | `.teamLead`("팀장", number 0), `.teammate(n)`("팀원" 또는 "팀원1·2…"). 세션 팀원과 서브에이전트가 한 번호 줄(`Agent.number`)을 씁니다 |
| 소속 파트 | `Agent.part` | 서브에이전트는 자기를 부른 세션의 파트 = 그 세션의 칸에 앉음 |
| 자리 | `Seat` (`Agent.seat`) | `Seat.office`(팀장실) 또는 `Seat(part:desk:)`: 칸 번호 + 칸 안 책상 번호(0 = 세션 팀원 자리, 서브에이전트는 1번부터, 4번 이상은 칸 앞에 서는 자리) (M4.5b) |

규칙:

1. **방 정하기** — 힌트의 조상 중 사무실에 있는 가장 가까운 세션의 방 → 힌트의 최상위 세션 폴더 방 → 자기 `cwd` 폴더 방. 폴더는 끝의 `/`를 떼고, `…/.claude/worktrees/<이름>`은 원래 폴더로 합칩니다 (방 이름도 원래 폴더 이름).
2. **직함** — 방의 첫 세션(메인 세션)이 팀장, 그 밖의 모든 사람(다른 세션, 서브에이전트)은 팀원입니다. 팀원 번호는 출근 때 비어 있는 가장 작은 번호로 정해 고정합니다. 방에 팀원이 1명이면 "팀원", 2명 이상이면 "팀원1", "팀원2"로 표시하므로, 두 번째 팀원이 오면 첫 팀원의 표시가 "팀원" → "팀원1"로 바뀝니다 (`Beat.retitled`). 에이전트 종류(code-reviewer, Explore …)는 이름에 쓰지 않고 신원 카드의 "에이전트" 줄에만 보여 줍니다 ("code-reviewer · 직접 만든 에이전트", "Explore · 기본 에이전트").
3. **메인 세션이 늦게 나타나면** (하위 세션이 먼저 이벤트를 보냄, 또는 정보 파일이 늦게 생김) — 지금 팀장이 그 세션의 하위 세션이면 팀장 자리를 넘겨받고, 먼저 와 있던 하위 세션은 팀원이 됩니다 (자리와 칸 맞바꿈, 빈 팀원 번호를 받음).
4. **승진** — 팀장 세션이 끝나면 방은 남은 세션이 있는 동안 유지되고, 가장 먼저 온 세션 팀원(order가 가장 작은)이 팀장으로 승진해 팀장실로 걸어가 앉습니다 (`Beat.promoted` → 정보 갱신, 이동, 환호·"제가 팀장 자리를 맡을게요!"). 팀원 번호는 내놓고, 그 세션의 서브에이전트는 팀장 칸(0번)으로 옮깁니다.
5. **방 닫기** — 사람이 모두 떠난 방은 닫힙니다 (`Beat.teamClosed` → `closeTeam`). 무대는 남은 직원이 문을 나간 뒤 그 방의 띠와 명패를 비우고(그 자리에 아무도 없을 때), 아래 방들은 직원과 함께 올라옵니다. 새 방은 비어 있는 가장 작은 방 번호(`island`, 색에 씀)를 다시 쓰고, 띠는 맨 아래에 붙습니다 (M4.5b, §8.1).
6. **이름 겹침 방지** — 화면 이름은 팀원 번호 규칙으로 겹치지 않습니다. 내부 프로필 이름(같은 종류의 고정 직원 "code-reviewer (2)")도 빈 번호를 다시 씁니다. 외형 키는 팀장 `lead@<방>`, 세션 팀원 `part@<방>#<칸 번호>`이고, 승진해도 얼굴은 그대로입니다 (같은 얼굴이 둘이 되면 출근 순번으로 바꿈).

### 6.1 연출 지시 (Directive)

```swift
public enum Directive: Equatable, Sendable {
    case spawn(AgentID, at: Spot)                     // 문 앞에 등장
    case walk(AgentID, to: Spot)                      // 길찾기 이동
    case sit(AgentID), stand(AgentID)
    case pose(AgentID, Pose)                          // 지속 동작: typing, reading, holdingCup …
    case gesture(AgentID, Gesture)                    // 1회성 동작: wave, nod, thumbsUp …
    case express(AgentID, Expression, for: Duration?) // 표정
    case emote(AgentID, Emote)                        // 머리 위 아이콘: ❗ ❓ 💡 💦 ✨ 💤 ♪
    case say(AgentID, Bubble)                         // 말풍선
    case status(AgentID, StatusPill?)                 // 머리 위 상태 칩 ("Edit · RouterConfig.java")
    case prop(AgentID, Prop?)                         // 들고 있는 소품: 책, 서류, 커피, 노트북
    case effect(Effect)                               // 종이비행기, 하이파이브 반짝임 등
    case sound(SoundCue)                              // 효과음 (§11). 재생 여부는 SoundPlayer가 설정을 보고 결정
    case despawn(AgentID)
}
```

### 6.3 깜빡임 방지 규칙 (가장 중요한 튜닝 포인트)

툴 호출은 수십 밀리초 단위로 연달아 일어나기 때문에, 그대로 그리면 캐릭터가 정신없이 움직입니다.

1. **최소 유지 시간:** 한 활동은 최소 2.5초 유지합니다. 그 사이 들어온 이벤트는 카테고리별로 최신 것만 남기고 합칩니다.
2. **이동 문턱:** 자리를 떠나는 이동은 "그 활동이 계속될 것"이라는 근거가 있을 때만 합니다.
   - read: 10초 안에 5회 이상
   - shell: `PostToolUse`가 2초 안에 오지 않음
   - web, plan: 즉시 이동 (보통 오래 걸리기 때문)
3. **우선순위:** 권한 대기 > 오류 > 위임·보고 대화 > 일반 활동 > 잡담. 높은 우선순위가 오면 이동 중이어도 즉시 반영합니다.
4. **이동 취소:** 목적지에 도착하기 전에 활동이 끝나면 그 자리에서 돌아섭니다.
5. **동시 이동 제한:** 한 팀에서 동시에 걷는 캐릭터는 최대 2명입니다.

### 6.4 M1 구현 메모 (설계에서 구체화하거나 바뀐 점)

- **두 단계 구조:** `OfficeState`(리듀서)가 이벤트를 받아 의미 단위의 `Beat`(출근, 위임, 보고, 승인 요청 …)를 내고, `Choreographer`가 `Beat`를 `Directive`로 바꿉니다. 앱은 `OfficeEngine` 하나만 들고 `handle(hookPayload:)`와 `tick(at:)`(0.25초 주기)만 부르면 됩니다.
- **직원별 대기열:** 씬은 직원마다 지시를 순서대로 실행합니다. `walk`와 `wait`는 다음 지시를 막고, 두 직원의 타이밍은 `signal`/`await`로 맞춥니다 (보고하러 온 팀원이 도착한 뒤 팀장이 하이파이브). 승인 요청·보고·퇴근처럼 급한 연출은 `clearQueue`로 시작합니다. `agent`가 없는 지시(팀 열기, 종이비행기, 알림성 효과음)는 바로 실행합니다.
- **유지 시간의 예외:** 더 바쁜 활동으로 바뀔 때(대기 → 생각 → 작업)는 2.5초를 기다리지 않고 바로 보여줍니다. 같은 등급끼리나 덜 바쁜 쪽으로 바뀔 때만 기다리고, 그 사이 들어온 활동은 최신 것만 남깁니다.
- ~~**읽기 횟수:** 책장 이동 판단(10초 안에 5회)~~ → 2026-11-08 책장을 없애 파일 읽기는 늘 자기 책상에서 합니다.
- **위임은 팀장 자리에서:** 팀장이 책장이나 서버랙에 있을 때 위임하면 먼저 자리로 돌아오고, 팀원은 팀장 자리로 찾아옵니다.
- **서브에이전트 연결:** `Agent` 툴의 PreToolUse로 팀원을 먼저 만들고, `SubagentStart`나 툴 이벤트의 `agent_id`를 같은 종류의 대기 중인 팀원에 묶습니다. `SubagentStart`를 받은 팀원과 백그라운드 위임(`run_in_background`)은 `PostToolUse(Agent)`가 먼저 와도 `SubagentStop`까지 남고, 그 밖의 팀원은 `PostToolUse(Agent)`에서 보고합니다 (§4.1 M0 결과).
- **공동 팀장:** 같은 폴더에서 세션을 여러 개 열면 같은 팀에 "팀장 2", "팀장 3"이 생깁니다.
- **대사 선택:** 주어진 정보(작업 이름, 직원 이름, 명령)를 가장 많이 쓰는 줄을 우선 고릅니다. 모든 대사는 해요체이며, 테스트가 반말 대사를 잡아냅니다.
- **효과음 위치:** 직원 대기열 안의 효과음(말풍선 블립, 문 종, 보고 소리)은 그 동작과 함께 울리고, 알림성 소리(노크, 뾰롱, 띠리링)는 바로 울립니다. 승인 요청 노크는 말풍선 블립 없이 노크만 울립니다.

### 6.5 M2 구현 메모

- **훅 서버는 Network.framework 대신 BSD 소켓으로** 만들었습니다 (`OfficeServer`). macOS와 Linux에서 같은 코드가 돌아서, 서버·토큰 검증·훅 스크립트를 클라우드에서도 끝에서 끝까지 테스트할 수 있습니다. `poll` 기반 대기 루프라 멈출 때 깔끔하게 끝납니다.
- 훅은 연결마다 동시에 받되 **도착 순서대로** 엔진에 넘깁니다. 병렬 툴 호출처럼 훅 자체가 동시에 실행되면 순서가 뒤바뀔 수 있어, 리듀서가 이미 끝난 `tool_use_id`의 늦은 시작을 무시합니다.
- **훅 스크립트는 동기 전송입니다** (§4.2). 백그라운드 curl은 Claude Code의 프로세스 그룹 정리 때문에 도착하지 못했습니다.
- 훅 스크립트는 앱 번들(패키지 리소스)에 들어 있고, 설치할 때 `~/.claude/hooks/claude-office.sh`로 복사합니다. 앱이 업데이트되어 스크립트가 바뀌면 "다시 설치" 배너가 뜹니다.
- 메뉴바 목록은 코어의 `Roster`가 만듭니다 (상태 이름, 승인 대기 모음, 표시 수준 적용). 앱은 그리기만 합니다.
- 앱 타깃은 Swift 5 언어 모드 + 최소 동시성 검사로 둡니다 (코어 패키지는 Swift 6). 서버 콜백은 `DispatchQueue.main`으로 옮겨 순서를 지킵니다.

### 6.6 M3 구현 메모

- **무대(Stage)를 렌더러와 분리했습니다** (`OfficeStage`, 순수 Swift). 직원별 대기열, 걷기 시간(거리 ÷ 120pt/초), `wait`, `signal`/`await`, 자리 예약을 무대가 처리하고, SpriteKit은 매 프레임 무대 상태를 그대로 옮겨 그리기만 합니다. 덕분에 Linux에서 시간을 흘려가며 테스트하고, 같은 그림 데이터로 SVG 스냅숏을 찍어 맥 없이 장면을 확인할 수 있습니다 (`make snapshot`, [예시](m3/)).
- **그림은 데이터입니다** (`OfficeArt`, `CharacterArt`). 미리보기의 SVG 도형을 그대로 옮겼고, SpriteKit(`SKShapeNode`)과 SVG 렌더러가 같은 데이터를 씁니다. 자세는 `RigAnimator`가 시각과 상태로 계산합니다 (숨쉬기, 깜빡임, 걷기, 타이핑, 손 들기, 제스처).
- **길찾기는 GameplayKit 대신 직접 구현한 A\***입니다 (16pt 격자, 8방향, 직선 줄이기). 책상·의자처럼 가구와 겹치는 자리는 "입구(approach)"까지 걸어간 뒤 한 걸음 들어갑니다.
- **배치:** 책상 섬은 두 열, 섬마다 책상 4개(팀장석은 가운데 왼쪽), 팀이 늘면 아래로 줄이 늘고 리서치 코너·휴게실이 따라 내려갑니다. 책상이 모자라면 섬 앞에 서서 일합니다.
- **급한 연출(clearQueue) 중에도 걷기는 목적지까지 계속합니다.** 중간에 멈추면 연출 엔진이 아는 위치와 어긋나기 때문입니다 (스냅숏에서 발견).
- 무대는 사무실 창이 닫혀 있어도 앱 모델이 30fps로 흘립니다. 창을 열면 그때의 모습이 바로 보입니다.
- 이름 충돌을 피하려고 `Expression`→`FacialExpression`, `Gesture`→`BodyGesture`로 바꿨습니다 (macOS의 Foundation·SwiftUI와 충돌).
- **캐릭터를 클릭하면 신원 카드**가 창 오른쪽 위에 뜹니다 (역할, 팀, 폴더, 지금 하는 일, 세션, 터미널). 고른 캐릭터 발밑에는 팀 색 고리가 깔리고, 빈 곳 클릭·✕·Esc로 닫습니다. 폴더와 세부 내용은 표시 수준이 "상세"일 때만 보입니다. 설계서 §10의 인스펙터는 M5에서 이 카드를 넓혀 만듭니다.
- **사무실 창 오른쪽에 직원 현황 패널**을 둡니다 (팀별 직원, 상태 칩, 지금 하는 일, 경과 시간). 줄을 누르면 사무실에서 그 캐릭터를 고른 것과 같고, 툴바 버튼으로 접습니다. 메뉴 목록·카드·패널의 얼굴은 모두 `CharacterArt.portrait`(사무실 캐릭터와 같은 부위 데이터)로 그립니다.
- 씬은 창 크기를 그대로 따르고(`resizeFill`), 사무실을 창에 맞게 줄여 위쪽 가운데에 둡니다. 창 비율이 달라 남는 곳은 벽과 바닥 무늬를 이어 그려 검은 여백이 없습니다 (`OfficeArt.layers(extent:)`).
- 명패처럼 상자 안 글자는 `SKLabelNode`의 `.center`(줄 높이 기준)가 아니라 "가H"의 글리프 높이 가운데로 맞춥니다.
- Esc는 SpriteKit 뷰가 먼저 받아 `onExitCommand`가 동작하지 않으므로, 사무실 창의 키 입력을 로컬 이벤트 모니터로 가로채 카드를 닫습니다.
- 책상 명패는 9.5pt 굵은 글씨로 키우고, 글자를 세로 가운데(`TextBaseline.central`)에 맞췄습니다. 긴 이름은 책상 폭에 맞춰 "…"로 줄입니다.

### 6.7 M4 구현 메모

### 6.9 M4.5b 구현 메모 (방 배치)

> M5(1)에서 팀장실·파트 칸·빈 책상 빌리기·리서치 데스크를 없애고 행 배치로 바꿨습니다 (§6.10). 아래는 그때의 기록입니다.

- **자리 모델:** `Seat(part:desk:)`와 `Seat.office`. 파트 번호가 곧 칸 번호라 코어(`OfficeState`)가 자리를 정하고, 무대는 칸 번호를 좌표로 바꾸기만 합니다. 팀장은 팀장실, 세션 팀원은 자기 칸의 0번(★) 책상, 서브에이전트는 자기 칸의 1번 책상부터 앉습니다 (고정 직원은 칸 안 지정석).
- **승진·자리 맞바꿈:** 파트 번호가 바뀌면 그 세션 직원의 자리도 새 칸으로 옮깁니다 (세션 팀원 → 팀장실, 서브에이전트 → 같은 번호 책상). 서브에이전트에게는 `Beat.reseated` → `refresh` + 이동을 냅니다. 팀장이 퇴근하면 팀장 서브에이전트도 함께 퇴근하므로 0번 칸이 비고, 승진한 세션 팀원의 서브에이전트가 그 칸으로 걸어갑니다.
- **빈 책상 빌리기 (칸 단위):** 책상이 없는 자리(칸에 4명 이상)의 서브에이전트는 ① 지금 빌린 책상 ② 자기 칸의 빈 책상(서브에이전트 책상 → ★ 자리) ③ 빈 칸(쓰는 파트가 없는 칸)의 책상 순으로 빌리고, 없으면 칸 앞에 섭니다. 다른 파트의 칸과 팀장실은 빌리지 않습니다. 주인(세션 팀원)이 휴게 공간·안마 의자에 가 있으면 그 ★ 자리도 빌릴 수 있고, 돌아오면 비켜 줍니다 (M4.5a 규칙 그대로).

- **탕비 코너:** 서버랙 자리(오른쪽 벽)에 냉장고·정수기·컵 선반. 쉬러 가는 길에 40%는 냉장고에서 캔 음료(`Prop.drink`)를 꺼내 들고 가고, 보고를 마친 서브에이전트의 35%는 정수기에서 물 한 잔(2.4초) 마시고 퇴근합니다. 확률은 난수열 대신 직원 id 해시로 정해 대사 선택에 영향을 주지 않고, 동시에 2명까지만 들릅니다 (§6.3: 이동은 쉬러 가거나 퇴근하는 순간에만 한 번).
- **리서치 데스크:** 지구본·스탠드를 없애고 창문 아래에 스탠딩 테이블(노트북 4대)을 두었습니다. 직원은 데스크 뒤(창 쪽)에 서서 화면 쪽을 봅니다.
- **말풍선 제한 단위:** `maxBubblesPerUnit = 3`을 칸 단위로 셉니다 (`Stage.bubbleUnit`: 팀장실은 따로, 팀장 서브에이전트는 0번 칸, 세션 팀원과 그 서브에이전트는 세션 팀원 칸). 칸이 바뀌면(승진) 기다리던 말풍선도 새 칸에서 다시 셉니다.
- **명패·칸 표지:** 명패는 `nameplates[방][Seat]`. 팀장실 "★ 팀장", 세션 팀원 칸의 첫 책상은 직함("팀원1"). 서브에이전트 책상에는 명패를 달지 않습니다 (에이전트 이름을 화면에 쓰지 않으므로). 칸마다 아래에 표지("팀장 칸", "팀원1 칸", 쓰는 파트가 없으면 옅은 "빈 칸")를 달고 러그도 옅게 깝니다. 팀장실 표지는 방 이름입니다.
- **공용 구역 넘침:** 정해진 자리(책장 3, 리서치 데스크 4, 화이트보드 2, 탕비 코너 2, 휴게 공간 4, 안마 의자 1)가 차면 구역 앞 격자(40×26pt, 걸을 수 있고 정해진 자리와 24pt 이상 떨어진 점)에서 가까운 순으로 예약해 섭니다. 예전처럼 한 점에 겹치지 않습니다.
- **상태 칩 묶기:** 같은 공용 구역에 칩이 3개 이상 뜨면 하나로 묶어 "책장 · 6명 읽는 중"처럼 보여 줍니다 (가장 많은 툴 종류로 동사를 정함). 칩이 위로 쌓여 화면 밖으로 잘리던 문제(혼잡 재현: 서버랙 9명)를 없앴습니다.
- **승인 대기의 이동 보정:** 승인 요청은 `clearQueue`로 시작하는데, 팀장 옆에서 자기 자리로 가는 이동이 대기열에 남아 있으면 함께 사라져 팀장 옆에 "앉는" 일이 있었습니다. 이제 손을 든 채로 연출 엔진이 아는 자리로 다시 걸어갑니다.
- 문(오른쪽 위)에서 왼쪽 위 팀장실까지 출입구로 돌아 들어가므로 팀장이 자리에 앉기까지 약 6.6초 걸립니다 (예전 3초 남짓). `make snapshot` 시각을 그에 맞춰 바꿨습니다 ([장면 예시](m4.5/)). 시나리오: `Scenarios/layout.jsonl`(방 배치), `Scenarios/crowd.jsonl`(혼잡 재현).

### 6.10 M5(1) 구현 메모 (행 배치와 메인 선택기 → 디렉토리 목록)

- **사용자 결정 (2026-11-08):** M4.5b 화면에서 팀원이 많아지자 사무실이 축소되어 보기 어려웠습니다. 그래서 ① 사무실은 줄이지 않고(배율 1) ② 직원 현황 위에서 볼 메인을 고르고 ③ 팀장 → "메인", 팀원 → "서브" ④ 팀장 칸·팀원 칸 분류, 팀장실 칸막이, 리서치 자리를 없애고 ⑤ 메인마다 한 행(가장 왼쪽 메인, 오른쪽 서브), 메인이 늘면 다음 행 ⑥ 사람 수만큼만 책상 ⑦ 넘치는 서브·메인은 우선 표시하지 않기로 했습니다. 이어서 행은 **최대 3개**, 탕비 코너·소파·안마 의자 등은 **위쪽에 모으고** 아래에 행이 나란히 들어가게 했습니다.
- **코어:** §5.1 규칙. `OfficeState.relabel`이 모든 사람의 직함을 한 번에 다시 정하고(메인 수는 사무실 전체, 서브 수는 행마다), `compactDesks`가 가운데 빈 책상을 오른쪽 끝 사람으로 메웁니다. 행 합치기는 `reconcileTeams`(메인의 조상이 다른 행에 있으면 그 행으로). M4.5a의 `reconcileLead`(같은 방 안 자리 맞바꿈)는 폴더 방이 없어져 필요 없어 지웠습니다. 고정 직원 지정석(`reservedSeats`)도 책상이 사람마다 생기므로 없앴습니다.
- **연출:** 빈 책상 빌리기(`makeRoom`·`borrowableDesks`)를 지웠습니다 — 사람마다 책상이 있습니다. 웹 검색은 자기 책상에서 타이핑. 자리가 바뀐 서브(`reseated`)·행이 바뀐 서브(합치기)는 자기 책상에 있으면 바로, 다른 곳에 있으면 돌아올 때 새 책상으로 갑니다. `Choreographer.restoreDirectives(for:entering:)`는 화면에 없던 직원을 엔진이 아는 지금 모습(자리, 앉음, 자세, 소품, 표정, 아이콘, 상태 칩, 승인 대기 외침 풍선)으로 다시 세우는 지시를 만듭니다.

  - **행 간격:** 최소 130 → 150(다섯째 수정에서 140). 화면이 높으면 3행이 아래 빈 공간까지 고르게 쓰도록 `OfficeLayout.rowSpacing(height:)` = (높이 − 36 − 첫 행 y) / 2로 벌립니다. 행이 하나여도 같은 간격 기준이라 행이 늘 때 위 행이 움직이지 않고, 창 높이가 바뀌면 직원도 행과 함께 옮겨집니다.
  - **뒷벽 다시 배치 (넷째 수정):** 순서를 정원 그림 액자(왼쪽, 최대 폭 380, 소파 위) → 벽시계(액자와 화이트보드 사이 가운데) → 화이트보드로 바꿨습니다. 액자와 화이트보드는 윗변 y 22로 올려 안마 의자 등판과 넉넉히 띄우고, 액자가 안마 의자 위로 넘어가지 않게 했습니다. 화이트보드와 출입문 사이는 72pt(이전 34). "입구"와 "탕비 코너" 라벨은 없앴습니다. 최소 폭 1100.
  - **둘레 여백:** 사무실 둘레 위·아래·왼쪽·오른쪽에 20pt 여백(`OfficeLayout.padding`)을 두고 여백에는 벽·바닥만 이어 그립니다(앱의 `OfficeScene.fitWorld`, SVG 스냅숏 모두). 사무실 크기는 여백 안쪽 크기를 따릅니다. 창 기본 크기는 1440×800, 사무실 최소 높이는 682(+ 여백 40)입니다.
  - **시계와 액자 (다섯째 수정):** 시계를 화이트보드 바로 왼쪽(사이 30pt)으로 붙이고, 정원 액자는 왼쪽에서 시계 앞 40pt까지 가로로 넓혔습니다(기본 사무실에서 약 480pt). 액자는 위로 올려 둔 덕분에 안마 의자 등판과 30pt 넘게 떨어져 있습니다.
  - **첫 행 내리기 (다섯째 수정):** 첫 행이 소파와 너무 붙어 있어 책상 줄 y를 342 → 366으로 내렸습니다. 행 간격 최솟값은 150 → 140으로 조금 줄였고, 기본 사무실(1140×708)에서 행 간격은 165 → 153입니다.
- **효과음:** 숨긴 사람의 소리는 무대에 오지 않지만, 전역 효과음(승인 요청 노크, 입력 대기, 응답 완료)은 그대로 울립니다.
- 시나리오: `Scenarios/floor.jsonl`(메인 4명, 서브 12명이 넘쳐 +2, 가운데 서브 퇴근 후 숨었던 서브가 들어옴, 셋째 행 메인 퇴근 후 넷째 메인의 행이 올라옴). `office-sim snapshot … --size 1400x648`로 창 크기를 바꿔 찍을 수 있습니다 ([장면 예시](m5/)). `office-sim replay`로 앱에 보내면 데스크톱 정보(힌트)는 붙지 않아 모든 세션이 메인으로 보입니다.

## 7. 말풍선과 대화 시스템

### 7.1 말풍선 종류

| 종류 | 모양 | 용도 |
|---|---|---|
| 말 (speech) | 둥근 사각형 + 꼬리 | 대화, 인사, 보고 |
| 생각 (thought) | 구름 + 작은 동그라미 꼬리 | 생각 중, 기다리는 중 |
| 외침 (shout) | 버터색 배경 + 굵은 테두리 + ❗ 배지 | **권한 승인 대기**, 중요 알림 |
| 속삭임 (whisper) | 작고 옅은 점선 테두리 | 휴게실 잡담 |
| 상태 칩 (status pill) | 머리 위 작은 알약 | 현재 툴과 대상 ("Edit · auth.ts") |

### 7.2 표시 규칙

- 캐릭터당 말풍선은 동시에 1개, 상태 칩은 별도 1개까지입니다.
- 표시 시간: `1.8초 + 글자당 60ms`, 최대 6초. 외침 풍선은 상황이 해결될 때까지 유지합니다.
- 길이: 미니 패널에서는 최대 18자, 메인 창에서는 최대 32자까지 보여주고 나머지는 `…`로 줄입니다. 마우스를 올리면 전체를 보여줍니다. (M4: 창 종류가 아니라 실제 표시 배율로 정합니다, §10.1)
- 겹침 방지: 가까운 말풍선끼리 겹치면 위쪽으로 쌓고, 화면 가장자리에서는 꼬리 방향을 바꿉니다.
- 팀 구역당 동시에 보이는 말풍선은 최대 3개입니다. 넘치면 우선순위가 낮은 것부터 대기열에 넣습니다.

### 7.3 대화 스크립트

말풍선 문구는 `OfficeCore/Resources/dialogue.ko.json`에 템플릿으로 둡니다. 같은 상황이라도 여러 문구 중 무작위로 골라 단조롭지 않게 합니다.

```json
{
  "delegate.lead":   ["{task} 부탁해요!", "{member}님, {task} 좀 봐줄래요?", "이거 맡아줄 수 있어요?"],
  "delegate.member": ["맡겨주세요!", "네, 바로 볼게요!", "오케이~"],
  "report.member":   ["다 했어요!", "끝났습니다!", "정리해서 드릴게요"],
  "report.lead":     ["고마워요!", "역시 최고예요", "완벽해요 👍"],
  "permission":      ["{subject} 실행해도 될까요?", "이거 해도 돼요?", "승인 부탁드려요!"],
  "error":           ["어라…?", "앗, 다시 해볼게요", "이상하네…"],
  "idle.chat":       ["커피 맛있어요", "오늘 빌드 잘 되네요", "점심 뭐 먹을까요?"]
}
```

**대화 스크립트 예시 (위임)**

```
t=0.0  팀장   gesture(.beckon)   say("RouterConfig 리뷰 부탁해요!")
t=0.3  팀원   spawn(at: .door) → walk(to: 팀장 옆)
t=2.5  팀원   gesture(.nod)      say("맡겨주세요!")   express(.excited)
t=4.0  팀원   walk(to: 팀원석) → sit → pose(.reading)
```

- **말투는 모든 캐릭터가 밝고 정중한 해요체로 통일합니다** (확정). 감탄사("앗", "오!")와 짧은 문장으로 아기자기한 느낌을 냅니다. 반말, 과한 유행어, 업무와 무관한 농담은 쓰지 않습니다.
- 잡담은 휴게실에 2명 이상 있을 때만, 1분에 최대 1회 나옵니다.
- (v2) LLM으로 잡담을 생성하는 옵션을 검토합니다. 비용과 개인정보 문제로 기본값은 꺼둡니다.

### 7.4 개인정보 표시 수준

말풍선과 상태 칩에는 파일명과 명령어가 나올 수 있습니다. 회의에서 화면을 공유할 때를 생각해서 3단계로 설정할 수 있게 합니다.

| 수준 | 예시 |
|---|---|
| 상세 (기본) | "Edit · RouterConfig.java", "`npm test` 실행해도 될까요?" |
| 요약 | "파일 편집 중", "명령 실행해도 될까요?" |
| 비공개 | 아이콘과 표정만 표시 |

- 프롬프트 내용(`UserPromptSubmit.prompt`)은 어떤 수준에서도 말풍선에 표시하지 않습니다.
- 명령어에 들어 있는 토큰, 비밀번호처럼 보이는 문자열(`--password`, `token=`, 긴 hex/base64)은 상세 수준에서도 가립니다.

## 8. 사무실 화면 (SpriteKit)

### 8.1 시점과 맵

- **3/4 탑다운 정면 시점**을 씁니다. 캐릭터는 항상 화면 쪽을 보고 앉도록 책상을 배치해서 **표정이 늘 보이게** 합니다.
- 사무실은 **배율 1**로 그리고, 맵 크기가 사무실 영역(창 크기 − 직원 현황 패널) 크기를 그대로 따릅니다 (둘레 여백 20pt 안쪽, 최소 1100×682, M5(1)). 길찾기 격자는 16pt입니다.
- 사무실은 **메인 하나 = 행 하나**입니다 (§5.1). 위쪽 뒷벽 앞에 공용 공간을 모으고, 아래에 행을 위에서부터 최대 3개 놓습니다. 화면에 들어가지 않는 행·서브는 그리지 않고 행 끝에 "+N"을 답니다 (§6.10).

```
┌──────────────────────────────────────────────────────────────────────────────────────┐
│ [──────── 정원 그림 액자 ────────]  시계 [화이트보드]       [출입문]  [냉장고][정수기][프린터] │ ← 뒷벽
│ [3인용 소파]  [3인용 소파]    (빈 공간)    [안마의자]  [안마의자]          (탕비 코너)     │ ← 공용 공간 (위쪽)
├──────────────────────────────────────────────────────────────────────────────────────┤
│ ★메인1   서브1  서브2  서브3  서브4  서브5  서브6  서브7  서브8  서브9  서브10  +2    │ ← 행 1 (한 행 최대 11명)
│ (폴더)                                                                               │
│ ★메인2   서브1  서브2  서브3                                                         │ ← 행 2
│ ★메인3   서브                                                                        │ ← 행 3 (최대 3행)
└──────────────────────────────────────────────────────────────────────────────────────┘
   둘레 여백 20pt 안쪽의 기본 사무실 1140×708 (창 1440×800). 메인이 늘면 다음 행, 서브가 오면 오른쪽 끝에 책상.
   첫 행 책상 줄 y 366, 행 간격은 최소 140이고 창이 높으면 3행이 아래 빈 공간까지 고르게 벌어짐
```

| 구역 | 연결 활동 |
|---|---|
| 행의 가장 왼쪽 책상 | 메인 자리 (★ 명패, 화분, 아래에 폴더 이름 표지). 위임·보고 때 서브가 부른 사람의 책상 뒤 통로 옆에 섬 |
| 행의 오른쪽 책상들 | 서브 자리 (사람 수만큼, 명패 "서브N"). 기본 업무, 파일 읽기, 오래 걸리는 셸 명령(⏳, 모니터 진행 표시), 웹 검색 |
| 화이트보드 | 계획 수립 (TodoWrite) |
| 휴게 공간 (위쪽 왼쪽: 3인용 소파 둘 · 빈 공간 · 안마 의자 둘) | 대기(60초 소파, 3분 안마 의자, 10분 잠), 잡담 |
| 탕비 코너 (냉장고·정수기·프린터, 오른쪽 벽) | 쉬러 가는 길에 음료, 퇴근 전에 물 한 잔 |
| 출입문 | 출근, 퇴근, 화면에 자리가 나서 다시 보이는 사람 |

- 행마다 메인 색 러그를 사람 수만큼 깔고, 책상 앞에 직함 명패를 답니다.
- 길찾기는 직접 구현한 A\*(16pt 격자)를 씁니다. 책상과 소파·큰 화분·안마 의자는 통과할 수 없고, 행과 행 사이는 행 끝을 돌아 지나갑니다.

### 8.2 시간대와 다크 모드

- macOS가 다크 모드이면 **야간 사무실**로 바뀝니다. 창밖이 밤하늘이 되고, 스탠드 조명이 따뜻하게 켜지고, 바닥색이 어두워집니다.
- (선택) 실제 시각에 맞춰 아침, 낮, 노을, 밤 4단계로 창밖 풍경을 바꿉니다.

### 8.3 성능 목표

| 항목 | 목표 |
|---|---|
| 프레임 | 30fps (`preferredFramesPerSecond = 30`), 변화가 없으면 렌더링 일시 정지 |
| CPU | 대기 상태 1% 미만, 활동 중 5% 미만 (M1 맥북 기준) |
| 메모리 | 150MB 미만 |
| 지연 | 훅 발생부터 화면 반영까지 300ms 미만 |
| 가려짐 | 창이 가려지거나 최소화되면 씬을 일시 정지 (`occlusionState`) |

| **설정** | `Settings` scene | 일반(로그인 시 실행: `SMAppService`), 연동(훅 설치·제거·상태 확인, 포트, 테스트 이벤트 보내기), 표시(말풍선 상세도, 미니 사무실 투명도, 동작 줄이기), 알림, **효과음**(§11), 직원 꾸미기 |

**상호작용**

- 캐릭터에 마우스 올리기: 이름표와 현재 작업 전체 문구
- 클릭: 인스펙터에서 상세 보기
- 더블클릭: 해당 세션의 터미널 앱을 앞으로 가져오기. `X-Office-Term` 값으로 앱을 고르고, VS Code이면 `cwd`를 엽니다. 특정 탭까지 찾아가는 기능은 v2에서 iTerm2부터 지원합니다.
- macOS **"동작 줄이기"** 설정을 따릅니다. 켜져 있으면 걷기 대신 순간이동하고, 제스처를 생략합니다.

**알림 (UNUserNotification)**

- 권한 승인 대기: 즉시 알림 + 메뉴바 배지
- 응답 완료(Stop): 기본은 끄고, 설정에서 켤 수 있습니다
- 알림을 클릭하면 해당 터미널로 이동합니다

### 10.1 미니 사무실 크기와 위치

**위치**

- 기본 위치는 화면 **오른쪽 아래**, 가장자리에서 16pt 떨어진 곳입니다.
- 드래그로 옮길 수 있습니다. 화면 모서리 근처(40pt 이내)에 놓으면 모서리에 자석처럼 붙습니다.
- **디스플레이마다** 마지막 위치와 크기를 기억합니다. 외장 모니터를 연결하거나 뺄 때 그 화면에서 쓰던 상태로 돌아갑니다.
- 창이 화면 밖으로 벗어나면(해상도 변경 등) 기본 위치로 되돌립니다.

**크기**

- 창의 가장자리나 모서리를 드래그해서 **자유롭게 늘리고 줄일 수 있습니다.** 최소 200×130pt, 최대는 화면의 사용 가능 영역 전체입니다.
- 기본은 비율 제한이 없고, ⌥(Option)를 누른 채 조절하면 현재 비율을 유지합니다.
- 크기 프리셋: 작게 240×160 / 보통 360×240 / 크게 560×360 / 화면 절반. 우클릭 메뉴와 메뉴바에서 고를 수 있습니다.
- 위쪽 손잡이를 더블클릭하면 "작게"와 직전 크기 사이를 오갑니다.
- 크기 조절 손잡이와 제목줄은 마우스를 올렸을 때만 나타납니다. 평소에는 사무실만 보입니다.

**카메라 (창 크기가 바뀔 때 보이는 범위)**

| 모드 | 동작 |
|---|---|
| 맞춤 (기본) | 선택한 범위가 창에 꽉 차도록 자동으로 확대·축소합니다. 범위는 사무실 전체 / 한 팀 / 따라가기(가장 바쁜 팀) 중에서 고릅니다 |
| 고정 배율 | 배율은 그대로 두고, 창을 키우면 더 넓은 영역이 보입니다 |

- 패널 안에서 트랙패드 핀치나 ⌘+스크롤로 확대·축소하고, 드래그로 화면을 옮길 수 있습니다. 더블클릭하면 맞춤 상태로 돌아갑니다.

**크기에 따른 표시 단계**

창이 작아질수록 글자가 뭉개지지 않게 보여주는 정보를 줄입니다. 기준은 창 크기가 아니라 **실제 표시 배율**(타일 32pt가 화면에서 차지하는 크기)입니다.

| 표시 배율 | 보여주는 것 |
|---|---|
| 0.5 미만 | 캐릭터, 표정, 머리 위 아이콘만. 말풍선은 외침 풍선만 (최대 10자) |
| 0.5 ~ 0.8 | 말풍선 최대 18자, 상태 칩 숨김, 명패 숨김 |
| 0.8 이상 | 말풍선 최대 32자, 상태 칩과 명패 표시 |

**구현 메모**

- `NSPanel` 스타일: `.nonactivatingPanel`, `.resizable`, `.titled` + `.fullSizeContentView`, 제목줄은 숨김. `contentMinSize`로 최솟값을 지정합니다.
- `SKView`는 `scaleMode = .resizeFill`로 두고, 창 크기가 바뀌면 `SKCameraNode`의 배율을 다시 계산합니다.
- 위치와 크기는 `NSScreen`의 디스플레이 ID를 키로 `UserDefaults`에 저장합니다.
- 크기 조절 중에는 렌더링을 30fps로 유지하고, 표시 단계는 조절이 끝난 뒤 0.2초 후에 바꿔서 깜빡임을 막습니다.

## 11. 효과음

### 11.1 원칙

- **작고 아기자기하게:** 길이 0.05~0.6초, 기본 음량 35%. 실로폰, 마림바, 오르골처럼 부드러운 톤만 씁니다. 날카로운 고음, 경고음, 긴 소리는 쓰지 않습니다.
- **종류별로 켜고 끕니다.** 전체 음소거와 전체 음량은 따로 있습니다.
- **알림성과 장식성을 구분합니다.** 놓치면 안 되는 소리(승인 요청, 완료)는 사무실이 안 보여도 울리고, 분위기용 소리는 사무실이 화면에 보일 때만 울립니다.
- **모두 직접 합성합니다.** 녹음 파일이나 외부 음원을 쓰지 않아 라이선스 문제가 없습니다.

### 11.2 효과음 목록

| 설정 항목 | 소리 | 언제 | 기본값 | 구분 |
|---|---|---|---|---|
| 승인 요청 | **똑똑** (나무 노크 2번) | 권한 승인 대기가 시작될 때. 30초마다 최대 2회 더 | 켬 | 알림 |
| 입력 대기 | **뾰롱** (부드러운 2음 하강) | Claude가 응답을 마치고 내 입력을 기다릴 때 | 켬 | 알림 |
| 작업 완료 | **띠리링** (실로폰 3음 상승) | 팀장 응답 완료(Stop). 팀원 보고(SubagentStop)는 더 짧은 2음 | 켬 | 알림 |

### 11.3 재생 규칙

- **전체 음소거:** 설정과 메뉴바 드롭다운에서 바로 켜고 끕니다.
- **전체 음량:** 0~100%, 기본 35%. 각 항목에는 미리 듣기 버튼이 있습니다.
- **장식성 소리:** 미니 사무실이나 메인 창이 화면에 보일 때만 재생합니다.
- **집중 모드 존중** (기본 켬): macOS 집중 모드가 켜져 있으면 알림성 소리도 끕니다. 시각 알림은 그대로 둡니다.
- **연속 재생 제한:** 같은 항목은 최소 간격을 둡니다(말풍선 0.4초, 완료 2초, 출근 1초). 동시에 울리는 소리는 최대 3개입니다.
- **우선순위:** 승인 요청 > 입력 대기 > 작업 완료 > 오류 > 나머지. 슬롯이 꽉 차면 낮은 소리부터 생략합니다.

### 11.4 캐릭터 목소리 (말풍선 블립)

- 직원마다 기본 음높이가 있습니다. 프로필 키의 해시로 5단계 중 하나를 고르며, 고정 직원은 항상 같은 목소리입니다.
- 말풍선 글자 수에 따라 블립을 2~4개 재생하고, 블립마다 ±2반음 범위에서 무작위로 음을 바꿉니다.
- 단어를 흉내 내는 음성 합성은 하지 않습니다. 짧은 톤만 씁니다.

### 11.5 구현

- `OfficeCore`에 `SoundCue`(무엇을 울릴지)와 `SoundRecipe`(파형, 음 목록, 엔벨로프)를 **데이터로** 정의합니다. 리눅스에서도 테스트할 수 있습니다.
- 연출 엔진은 `Directive.sound(SoundCue)`를 내보내고, 앱의 `SoundPlayer`가 설정(켜짐 여부, 음량, 연속 재생 제한)을 확인한 뒤 재생합니다.
- 앱이 시작될 때 레시피로 `AVAudioPCMBuffer`를 미리 합성해 둡니다. 재생은 `AVAudioEngine` + `AVAudioPlayerNode` 4개 풀, 캐릭터별 음높이는 `AVAudioUnitTimePitch`를 씁니다.
- 설정은 `UserDefaults`에 `sound.enabled`, `sound.volume`, `sound.<항목>.enabled`로 저장합니다.
- [스타일 미리보기](preview/index.html)의 효과음 섹션은 같은 레시피를 Web Audio로 들려주는 시안입니다.

## 12. 보안과 배포

### 12.1 로컬 서버 보안

- `127.0.0.1`에만 바인딩합니다. 외부 네트워크에서는 접근할 수 없습니다.
- 모든 요청에 `X-Office-Token`을 검증합니다. 토큰은 앱이 실행될 때마다 새로 만들어 `endpoint` 파일(권한 600)에 기록합니다.
- `Origin` 헤더가 있는 요청은 거부합니다. 웹 페이지가 브라우저를 통해 로컬 서버를 호출하는 공격(CSRF, DNS 리바인딩)을 막기 위해서입니다.
- 본문 크기는 1MB로 제한하고, JSON만 받습니다.
- 받은 데이터는 메모리에만 두고(세션당 최근 1,000건), 디스크에는 직원 프로필과 설정만 저장합니다.

### 12.2 배포

- **샌드박스를 쓰지 않는 앱**입니다. `~/.claude`를 읽고 `settings.json`을 수정해야 하기 때문입니다. 따라서 App Store에는 내지 않습니다.
- 1단계: **소스 빌드** (`make install`). 연회비가 필요 없습니다.
- 2단계(선택): Developer ID 서명 + 공증, DMG, Sparkle 자동 업데이트, Homebrew Cask
- 앱 이름에 "Claude"가 들어가므로, 불특정 다수에게 공개 배포할 때는 Anthropic의 상표 사용 정책을 먼저 확인합니다. 본인용과 소스 빌드 단계에서는 해당 없습니다.

## 16. 위험 요소와 대응

| 위험 | 대응 |
|---|---|
| Claude Code 업데이트로 훅 페이로드가 바뀜 | 관대한 파서, 알 수 없는 필드 무시, 버전별 픽스처 테스트 |

| 화면 공유 중 정보 노출 | §7.4 표시 수준, 프롬프트 비표시, 민감 문자열 가리기 |
